# update.md — журнал изменений TouchCursor

## v1.2 — исправление обрыва Wi-Fi-соединения при включении управления и касаниях

### Симптом
При подключении по Wi-Fi приложение соединялось с компьютером, но после включения
управления и нажатия экранных кнопок или движения пальцем по тачпаду в консоли
`TouchCursorServer.exe` появлялось сообщение «Клиент отключился», а затем клиент
автоматически переподключался.

### Найденные причины и исправления

**Сервер (`windows_server/touchcursor_server/server.py`):**

1. **Падение потока-обработчика из-за непрехваченного исключения.**
   Обработка команд шла внутри `ClientHandler.run()`; любое исключение, возникшее
   ниже защищённого блока (например, при отправке ответа в уже закрытый сокет),
   убивало поток целиком — сокет закрывался в `finally()`, и сервер фиксировал
   «Клиент отключился». Разбор каждой команды вынесен в метод `_dispatch()`,
   вызываемый из `handle_line()` через дополнительный `try/except Exception`.
   Теперь одна битая/неожиданная команда не рвёт соединение.

2. **Неограниченный рост буфера при потоке данных без переводов строк.**
   Если в канале не встречался байт `\n` (битый транспорт, мусор, разрыв посреди
   строки), буфер `self.buf` рос бесконечно вплоть до `MemoryError`, который так
   же обрывал сессию. Добавлен лимит `MAX_LINE_BYTES = 64 KiB`: при переполнении
   буфер сбрасывается с предупреждением в логе, соединение остаётся живым.

3. **Чтение канала защищено общим `except Exception`** с записью причины в лог —
   раньше любые нестандартные ошибки транспорта приводили к молчаливой смерти
   потока без диагностики.

**Клиент Android (`PcClient.java`, `ControlService.java`):**

4. **Гонка двух экземпляров клиента.** При пересоздании активности (поворот
   экрана, перезапуск) старый цикл переподключения мог в своём `finally()`
   закрыть ТРАНСПОРТ, который уже был опубликован новым экземпляром, — живой
   канал рвался ровно в момент включения управления. Публикация и снятие канала
   (`transport`/`out`/`connected`) теперь выполняются атомарно под мьютексом
   `connLock`; поток закрывает только СВОЙ транспорт (`wasMine`-проверка).

5. **Запись в потерянный канал больше не закрывает транспорт «вслепую».**
   В `writeLine()` ссылка на поток копируется под мьютексом; при ошибке записи
   устаревший экземпляр канала просто игнорируется, а актуальный помечается
   мёртвым — переподключение выполняет штатный `connectLoop`.

6. **Идемпотентный `startControlling()`.** Повторный вызов с теми же параметрами
   канала (mode/ip/port/btMac/deviceName — сравнение через новый метод
   `PcClient.sameParams()`) больше НЕ разрывает живое соединение. Переподключение
   происходит только при реальном изменении параметров (смена канала Wi-Fi/USB/BT).

### Проверки
* Смоук-тест сервера на Linux с моками WinAPI: TCP-сессия из 500+ move-событий,
  кликов, down/up, скролла и ЗАВЕДОМО БИТЫХ команд (`x:"broken"`, кнопка `middle`) —
  соединение не разрывается, на ошибки приходят ответы `{"resp":"err",...}`,
  последующие валидные команды исполняются. Стрим мусора без `\n` объёмом 138 КБ
  приводит к штатному сбросу буфера, поток жив.
* Компиляция Java-классов против заглушек Android-API — новых ошибок нет.

### Что нужно сделать пользователю
1. Забрать обновлённые файлы проекта (или собрать архив `TouchCursor-project_v1.2.zip`).
2. **Пересобрать EXE-сервер**: `build_exe.bat` (Wi-Fi-вариант) — изменения только на стороне Python.
3. **Пересобрать APK** в Android Studio (изменены `PcClient.java`, `ControlService.java`).
4. Установить новое приложение и запустить новый `TouchCursorServer.exe`.

## Ранее (v1.1 и ниже) — краткая сводка
* Подключение по USB (AOA) и Bluetooth (RFCOMM/SPP) + кнопки выбора канала внизу экрана.
* Кнопки «−/+» скорости перемещения курсора (уровни 1–10).
* Сборка Windows-сервера в один EXE (PyInstaller, ctypes вместо pywin32):
  `build_exe.bat`, `build_exe_bt.bat`, `build_exe_usb.bat`.
* Исправления сборки APK: FOREGROUND_SERVICE-разрешения (краш ControlService),
  динамические права Android 12+/13+, BT-транспорт (isConnected/getDefaultAdapter),
  UsbTransport (IOException), TouchPadView (getString), иконка launcher,
  non-ASCII путь проекта, предупреждения Gradle.
* Портретная ориентация (fullSensor + layout-port/layout-land, кнопки одной высоты).
* Подсветка экранных кнопок ЛКМ/ЛКМ×2/ПКМ единым цветом при нажатии Громкость+/−
  (отдельные индикаторы убраны; подсветка = pressed-состояние самих кнопок).
* Руководство `docs/РУКОВОДСТВО_ПОДКЛЮЧЕНИЯ.md`.
