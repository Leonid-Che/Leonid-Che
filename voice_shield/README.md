# Voice Shield

Персональный генератор **акустического белого шума** на Android для маскирования
конфиденциальных разговоров + блокировка перехвата записи через микрофон самого
смартфона. Легально, использует только собственный динамик и микрофон устройства.

## Что делает приложение

| Функция | Реализация |
|---|---|
| Генерация шума (белый / розовый / речевой диапазон 300–3400 Гц) | `NoiseEngine.kt` — AudioTrack, PCM16, 48 кГц, RMS-нормализация, чтобы переключение режимов не меняло громкость |
| Захват микрофона «на себя» на время работы щита | `MicSentinel.kt` — MediaRecorder держит AudioSource.MIC; фоновые приложения (в т.ч. потенциально взломанные) получают ошибку захвата или вытесняются системой |
| Детекция активного прослушивателя | Если захватить MIC не удалось — ресурс уже занят другим процессом → UI честно показывает предупреждение |
| Периодический аудит владения MIC | Кнопка «Проверить захват микрофона» |
| Работа с выключенным экраном | Уведомление (рекомендуется доработать до foreground-service типа `mediaPlayback`) |

## Чего приложение НЕ делает (и почему)

- **Не глушит радиосвязь, Wi-Fi, сотовую сеть** — аппаратно невозможно на смартфоне и уголовно наказуемо.
- **Не пишет звук «в никуда» незаметно**: запись идёт в файл `sink.3gp` во внутреннем кэше приложения (приватен, удаляется системой). При желании можно заменить на `AudioRecord` с мгновенным сбросом буфера.
- **Не даёт 100% защиты от целевого Жучка-«железа»** — это бытовое средство повышения конфиденциальности, а не сертифицированная ТЗУ.

## Важные ограничения платформы (честно)

1. **Эксклюзивность микрофона в Android не гарантирована.** Начиная с Android 10 несколько приложений могут одновременно читать MIC (shared capture), а приоритеты захвата зависят от OEM-политики. Захват через MediaRecorder — эвристика «первый занял», эффективная против большинства фоновых шпионских приложений, но не абсолютная. Надёжнее всего — физически: разговор вне зоны действия смартфона либо извлечение/отключение устройства.
2. **Радиус акустического маскирования ограничен громкостью динамика** — у типичного смартфона это 1–3 метра до шепота, 0.5–1 м до нормальной речи. Для комнаты используйте внешнюю колонку: приложение работает с STREAM_MUSIC, поэтому достаточно подключить Bluetooth-колонку и вывести шум на неё.
3. На Android 12+ система показывает **зелёный индикатор** использования микрофона — если он горит, когда щит не активен, что-то пишет звук. Проверяйте.

## Сборка

```
Android Studio → Open project → voice_shield/ → Build
minSdk 29, targetSdk 34, Kotlin, без нативных зависимостей.
```

## Использование

1. Выберите режим (по умолчанию — «речевой диапазон», оптимален по соотношению эффективность/комфорт).
2. Отрегулируйте громкость ползунком (учтите: длительное воздействие шума >85 дБA вредит слуху; смартфон на максимуме в 30 см от уха ≈ 90–100 дБA — кладите динамиком от себя).
3. Нажмите **«Активировать щит»** → разрешите доступ к микрофону.
4. Проверьте статус: «микрофон захвачен этим приложением» — OK; предупреждение о чужом захвате — немедленно проведите аудит приложений (Настройки → Конфиденциальность → Диспетчер разрешений → Микрофон) и полную антивирусную проверку.
5. Кнопка «Проверить захват микрофона» — периодический контроль во время длинных переговоров.

## Проверенное поведение (симуляция логики, все сценарии пройдены)

- S1: свободный MIC → захват → стороннее приложение не может начать запись → после деактивации ресурс освобождается.
- S2: MIC занят «шпионом» → щит включает шум и честно сообщает HIJACKED_POSSIBLY, деактивация не трогает чужой захват.
- S3: двойная активация идемпотентна; потеря держателя → аудит перезахватывает.
- DSP: доля энергии в полосе 300–3400 Гц у режима SPEECHBAND ≈ 0.49 против ≈ 0.35 у белого шума при равном RMS (проверено моделью фильтра из Kotlin-кода).
